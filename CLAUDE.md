# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

CourseWorkMaker (md2docx) — онлайн-редактор Markdown с живым постраничным превью «как в Word» и серверной конвертацией в DOCX по **ГОСТ 7.32-2017**, плюс ИИ-агент (LangChain через OpenAI-совместимый прокси Polza.ai; конкретная модель скрыта за уровнем качества, см. `AI_MODEL_*`), генерирующий курсовую целиком. Документация и комментарии в коде — на русском. Текст самого стандарта лежит в корне репозитория (`ГОСТ 7.32-2017.pdf`) — при вопросах об оформлении сверяйся с ним, а не с памятью.

Более широкий справочник (таблицы стека, портов, эндпоинтов, переменных окружения) — в `AGENTS.md`. Этот файл (`CLAUDE.md`) фокусируется на неочевидных инвариантах, которые нельзя вывести из кода.

## Commands

```bash
# Полный запуск (нужен .env с JWT_SECRET; AI_API_KEY — только для ИИ)
docker compose up --build          # фронт: http://localhost:3000, шлюз: :8080

# Режим разработки: бэкенд в докере, фронт с hot-reload
docker compose up postgres gateway auth-service document-service converter-service ai-service
cd frontend && npm install && npm run dev   # http://localhost:5173, vite проксирует /api на :8080

# Сборка/тайпчек фронтенда
cd frontend && npm run build       # tsc -b && vite build

# Тесты фронтенда (vitest + happy-dom: парсер, ГОСТ-рендер, метрики)
cd frontend && npm run test

# Тесты Python-сервисов (гоняются в docker — локальный python может быть старым)
cd services/converter   # или services/ai (тег образа: cwm-ai)
docker build -t cwm-converter . && docker run --rm -v "$PWD/tests:/srv/tests" cwm-converter python -m pytest tests -q
# один тест: ... python -m pytest tests -q -k <name>
```

Java-сервисы (gateway, auth, document) собираются Gradle'ом внутри своих Dockerfile — локального gradle wrapper нет, пересборка через `docker compose build <service>`.

Гочи деплоя: `docker compose restart` **не** перечитывает `.env` — нужен `docker compose up -d <service>`; docker-сборка иногда тихо не обновляет образ (кэш) — после деплоя сверяй артефакт в контейнере (converter: grep правки в `app/gost.py`; frontend: имя бандла `index-<hash>.js` в `dist/` vs контейнер).

## Architecture

Микросервисы за единым шлюзом. Браузер → `frontend` (React+TS+Vite+Tailwind, nginx) → `/api` → `gateway` (Spring Cloud Gateway, :8080) → внутренние сервисы:

- `services/auth` — Spring Boot :8081, JWT (HS256, JJWT), BCrypt, Flyway, БД `auth_db`
- `services/document` — Spring Boot :8082, документы пользователя (markdown + настройки), БД `document_db`
- `services/converter` — FastAPI :8001, python-docx, MD → DOCX по ГОСТ; формулы LaTeX→OMML через **Pandoc** (`omml.py`); PDF-экспорт через **LibreOffice** (`pdf.py`: Basic-макрос обновляет поле содержания перед экспортом, профиль-шаблон готовится при сборке образа)
- `services/ai` — FastAPI :8002, LangChain + OpenAI-совместимый прокси Polza.ai (`AI_API_KEY`/`AI_BASE_URL`; модели скрыты за уровнями качества `AI_MODEL_FAST`/`AI_MODEL_BALANCED`/`AI_MODEL_QUALITY`, формат `provider/model`), асинхронные job'ы с отменой (`/jobs/{id}/cancel`) и ценами (`/pricing`)

### Безопасность (инвариант)

JWT проверяет **только** gateway (`gateway/.../security/JwtAuthFilter.java`); внутрь личность передаётся заголовком `X-User-Id`, а клиентские `X-User-*` всегда вырезаются на шлюзе. Внутренние сервисы доверяют `X-User-Id` без проверки токена. Публичны только `POST /api/auth/login` и `/api/auth/register`. Загрузка картинок по URL защищена от SSRF в обоих Python-сервисах (`converter/app/images.py`, `ai/app/web_images.py`: приватные адреса блокируются, лимит 10 МБ).

### Два параллельных рендера ГОСТ (главный инвариант)

Превью и DOCX реализованы **дважды** и должны давать идентичный результат — вплоть до совпадения числа страниц и номеров страниц в содержании (проверено на `tests/data/kalman-report.md`: превью и PDF из DOCX дают одинаковые 46 страниц и одинаковое содержание).

**Метрики строки (не трогать поодиночке!)**: «полуторный» интервал Word — это 1,5 × собственная высота строки шрифта (hhea-метрики), а НЕ 1,5 em. Калибровано по PDF LibreOffice: Times New Roman 14 пт → 24,15 пт/строка (`LINE_HEIGHT='1.725'` в gostRender.ts ↔ `LINE_PT=Pt(24.15)` в gost.py), Courier New 12 пт в листингах → 20,4 пт (`LINE_HEIGHT_CODE='1.7'`), одинарный интервал (подписи рисунков) → `1.15`. Пагинатор меряет высоты через `getBoundingClientRect().height` (дробные px!) — `offsetHeight` округляет и накапливает ошибку до переполнения страницы. Все свободные строки — НАСТОЯЩИЕ пустые абзацы DOCX (Word показывает их и вверху листа; превью их не гасит), `isBlank` — только маркер дедупликации служебных свободных строк; `space_before` в DOCX больше не используется для свободных строк (историческая справка: Word гасит space_before в начале страницы — механизм убран 2026-07-13 по требованию пользователя «нормоконтролю нужны пустые строки, а не интервалы»). Картинки: px→мм по 96 dpi, если плотность не задана явно (python-docx для PNG без pHYs возвращает 72 — трактуется как 96); mermaid-PNG растрируется с масштабом k и получает pHYs 96·k dpi (`pngWithDpi` в mermaidRenderer.ts), чтобы конвертер получил те же мм, что показывает превью; заглушка отсутствующей картинки — рамка 125×62 мм на обеих сторонах.

- **Фронтенд**: `frontend/src/lib/markdown.ts` (парсер в блочную модель) → `gostRender.ts` (блоки → HTML по ГОСТ: нумерация разделов/рисунков/таблиц/формул, титульник, содержание) → `paginate.ts` (разбивка на страницы А4 измерением реальных высот в скрытом DOM-хосте).

Титульный лист — свободные многострочные блоки в настройках (titleHeader/titleWork/topic/titlePeople/titleBottom + titleLogo-ассет), покрывают и курсовую по ГОСТ, и отчёты по лабораторным (несколько исполнителей, «Принял:», логотип вуза). Формат строк исполнителей: «Метка: текст» → метка слева, текст у правого поля. Строка «вся прописными» в titleWork рендерится крупно. Старые фиксированные поля (university/student/…) мигрируются в `migrateSettings` (settings.ts) при загрузке из localStorage и облака; логотип — ассет вне markdown: его хранит `pruneAssets(md, keep)` и явно передаёт конвертеру `download()`.

Свой титульник файлом: `POST /convert/title-image` (конвертер) рендерит первую страницу PDF/DOCX в PNG (docx→pdf через LibreOffice, pdf→png через pdftoppm/poppler); фронт хранит PNG ассетом в `settings.titleCustom` — превью показывает его полностраничной картинкой, DOCX вставляет секцией с нулевыми полями (контент — вторая секция с ГОСТ-полями, номер страницы в footer второй секции, титул без номера).
- **Бэкенд**: `services/converter/app/md_parser.py` (парсер, согласован с фронтендовым) → `gost.py` (сборка .docx: поля/шрифты/интервалы по ГОСТ, настоящее TOC-поле Word, OMML-формулы через `omml.py` — он гоняет каждую формулу через **pandoc** `markdown→docx` и извлекает `<m:oMath>`, с кэшем).

Конвертация .docx — **серверная** (кнопка «Скачать» → `convertApi.docx` → шлюз → converter). Был эксперимент с client-side генерацией на TS (`docx`-либа), но от него отказались из-за низкого качества формул (KaTeX MathML→mml2omml); Pandoc даёт родной OMML.

Списки (маркированные и нумерованные) верстаются как обычный абзац с красной строки: маркер («–» или «N)») на абзацном отступе 1,25 см, после маркера NBSP (текст не отрывается от маркера), продолжение длинного пункта переносится к ЛЕВОМУ полю — висячего отступа НЕТ (решение пользователя, июль 2026; ранее был hanging-отступ с текстом на 2 см — откатили). В DOCX это `first_line_indent=INDENT` без `left_indent` и без табов (`_list` в gost.py), в превью — `text-indent:12.5mm` без `padding-left` (renderAll). Список источников — та же вёрстка, но номер БЕЗ скобки и точки.

Правила оформления согласованы между сторонами: заголовки и подзаголовки — БЕЗ дополнительных интервалов до/после (решение пользователя, июль 2026: везде обычный полуторный интервал; space_before/space_after = 0 у стилей Heading 1..3 в gost.py ↔ в превью заголовки — обычные строки без спейсеров и padding); хвостовая точка заголовков срезается парсерами; пояснения к формуле («где …» и каждое следующее) — отдельными абзацами с красной строки; список источников — номер С ТОЧКОЙ («1.») с абзацного отступа как обычный текст, не висячий (решение пользователя 2026-07-13: вуз требует точку, хотя выписка ГОСТ 6.16 говорит «без точки»); содержание — отступы 0/0,5/1 см (стили TOC 1..3 ↔ buildTocRow), «СОДЕРЖАНИЕ» без отступа после, у стилей TOC ЯВНЫЕ space_before/after=0 (они создаются без basedOn и иначе наследуют docDefaults шаблона python-docx — space_after 8 пт разрежал содержание против превью); подписи рисунков и таблиц — одинарный интервал (многострочная подпись — через один интервал), подпись таблицы ВПЛОТНУЮ к таблице (space_after=0, line_spacing=1.0 ↔ line-height:1.15 у capHtml); номера страниц — кеглем основного текста (14 пт) на позиции 10 мм от низа; `# Реферат` первым заголовком — его страницы идут ДО содержания и в содержание не входят (обе стороны: `_split_referat` в gost.py ↔ split в paginate.ts, outlineLvl=9 исключает из поля TOC).

Правила переносов согласованы между сторонами: разделы `#` — с новой страницы; заголовок «съедает» идущие сразу за ним пустые строки — между заголовком и текстом не бывает лишнего пустого абзаца, интервал там обычный полуторный межстрочный (оба парсера отбрасывают такой blank ДО рендера: `dropBlankAfterHeading` в markdown.ts ↔ `_drop_blank_after_heading` в md_parser.py — это исключение из «настоящие пустые абзацы Word показывает всегда»); заголовки, подписи таблиц/рисунков и формулы с «где» не отрываются от следующего блока (keep_with_next ↔ keepNext; в превью keepNext требует места лишь для СТАРТА соседа — 2 строки делимого блока ПЛЮС строка запаса на дребезг переносов слов Chrome↔Word, а не для целого абзаца — калибровано по kalman-report, заголовки 3.2/5.3); шапка таблицы не остаётся одна внизу страницы — липнет к первой строке тела (keep_with_next в ячейках шапки ↔ minFirst в paginate.ts; ВАЖНО: без этого LibreOffice при экспорте в PDF ТЕРЯЛ все строки тела таблицы, разорванной сразу после tblHeader-строки); свободная строка до и после таблиц/рисунков/схем/листингов/формул — НАСТОЯЩИЙ пустой абзац с обеих сторон (решение пользователя 2026-07-13: нормоконтроль ждёт пустую строку, а не межабзацный интервал; в DOCX — needs_lead/pending_free в build(), один абзац «на двоих» между соседними блоками; в превью — blank-блоки, isBlank теперь ТОЛЬКО маркер дедупа, пагинатор их НЕ гасит — Word пустые абзацы показывает и вверху листа); служебный blank точно на границе листа превью кладёт с допуском BLANK_EDGE_TOL_PX≈3мм, урезая до остатка (дребезг высот Chrome↔Word; калибровано по свободной строке после Таблицы 5 kalman-report); многостраничная таблица повторяет шапку (w:tblHeader ↔ повтор thead в пагинаторе), всегда занимает 100% ширины (w:tblW pct ↔ width:100%), а шире 6 колонок — кегль 12 пт (обе стороны); патологические габариты (таблица >8 колонок, mermaid >20 строк) ловит линт агента и нормоконтроль (`_lint_oversized`), а не вёрстка; делимые блоки в превью соблюдают widow/orphan-контроль, а сплошной абзац, не влезающий в остаток страницы, режется по словам (cutHtmlLine) с минимум двумя строками с каждой стороны разреза — как разрыв абзаца в Word; если при разрезе хвосту не хватает двух строк, строка ОТДАЁТСЯ ИЗ ГОЛОВЫ (пере-рез с бюджетом h−2 строки), а не переносится весь абзац — Word делает так же (пояснения «где …» — такие же делимые абзацы); содержание в превью пагинируется измерением реальных высот строк (packToc), отточие — символами точки. Длинные слова/URL ломаются по символам (overflow-wrap ↔ поведение Word).

Проверка вёрстки превью: dev-харнесс `frontend/preview-test.html` (`npm run dev` → http://localhost:5173/preview-test.html?doc=toc|code|wide|mixed|report&page=N) рендерит страницы А4 с диагностикой «ПЕРЕПОЛНЕНИЕ N px» на каждой; `&debug=1` печатает под каждой страницей её блоки с реальными высотами в мм (диагностика расхождений с PDF); скриншоты — headless Chrome. Меняя пагинацию/рендер, прогони все сценарии. Сценарий `report` — полная курсовая (фикстура `frontend/src/fixtures/kalman-report.md`, копия `services/converter/tests/data/kalman-report.md` — менять только парой): сверяй его число страниц и номера в содержании с PDF конвертера (`docx_to_pdf` на той же фикстуре) — они обязаны совпадать. Юнит-тесты правил рендера — `frontend/src/lib/gostRender.test.ts` (vitest, зеркалит `services/converter/tests/test_gost_layout.py`).

Меняя поддерживаемый Markdown-диалект или правила оформления, правь **обе** стороны. Диалект описан в README («Диалект Markdown»): `#` — раздел с новой страницы и автонумерацией, структурные заголовки (ВВЕДЕНИЕ/ЗАКЛЮЧЕНИЕ/СПИСОК…) — прописными по центру, строки-подписи `Таблица: …` / `Рисунок: …` перед таблицей/картинкой, `$$…$$`/`$…$` — формулы Word (OMML), mermaid рендерится фронтендом в PNG (`mermaidRenderer.ts`) и передаётся конвертеру в `assets`.

### Редактор: overlay-подсветка (инвариант)

Редактор — это `<textarea>` + слой `<pre>` с подсветкой (`frontend/src/lib/highlight.ts`), которые обязаны переносить строки одинаково. В стилях подсветки допустимы только цвет/фон/border-radius — любые padding/margin/font-size/font-family в span'ах разъезжают курсор с текстом (симптомы: «плывут интервалы», «правлю одну строку — меняется другая»). Это касается и подсветки кода внутри ```-блоков (`hlCode`: токены собираются по сырой строке одним проходом с отбросом пересечений). Визуальная проверка подсветки — dev-страница `frontend/highlight-test.html` (обе темы).

### ИИ-агент (`services/ai/app/agent.py`)

Конвейер: план (строгий JSON) → генерация разделов по одному с контекстом плана и загруженных файлов (PDF/DOCX/TXT/MD, `files.py`) → самопроверка «нормоконтролёром» (temperature=0) → программный линт структуры + исправляющий вызов → построение графиков. При `include_images` ИИ пишет скрипты в блоках ` ```matplotlib `, а `figures.py`/`matplotlib_exec.py` выполняют их в изолированном подпроцессе (AST-блоклист, RLIMIT_CPU, таймаут 30с) и встраивают PNG как ассеты `asset:fig-N` (возвращаются в ответе job вместе с markdown — фронт кладёт их в хранилище, конвертер встраивает в DOCX). Polza — чистый прокси моделей (без code-interpreter), поэтому исполнение скриптов только на нашей стороне. Задачи асинхронные: `POST /api/ai/generate` → `jobId`, опрос `GET /api/ai/jobs/{id}` (`jobs.py`); прогресс показывается в UI. Поле `partial` job'а — готовые разделы по мере генерации (живой предпросмотр в AiModal; при отмене partial предлагается в diff-просмотре). Без `AI_API_KEY` сервис возвращает понятную ошибку «не сконфигурирован».

Чистая логика агента (нормализация плана `normalize_outline`, страховка заголовков `ensure_single_heading`, `split_sections`/`replace_section`, линты `lint_document`/`lint_user_document`, бюджет слов) — функции уровня модуля в `agent.py`, покрыты тестами в `services/ai/tests/`. `POST /api/ai/lint` — нормоконтроль документа пользователя без LLM (кнопка в статус-баре, работает без ключа; `check_urls` проверяет ссылки источников, `sources.py`). `POST /api/ai/edit-section` — правка одного раздела (модель получает план + раздел, ответ подшивается программно). Правки (`/edit`, `/edit-section`) применяются на фронте только после diff-просмотра (`DiffModal.tsx`, `lib/diff.ts`); текст до применения сохраняется (`storage.ts`, кнопка «Откатить ИИ-правку»).
