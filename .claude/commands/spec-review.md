Проревьюируй спеку: $ARGUMENTS

Если аргумент пуст — возьми спеки, изменённые относительно develop
(`git diff develop --name-only -- docs/specs/`, включая незакоммиченное).
Процесс SDD описан в docs/README.md.

Проверь:
1. Внутренние противоречия и противоречия с другими спеками в docs/specs/.
2. Противоречия с текущим кодом — с указанием файла:строки.
3. Недоопределённые граничные случаи — сформулируй их как вопросы ко мне.
4. Для пунктов со статусом «принят» — проверяемость: можно ли по формулировке
   написать тест; если нет — предложи, чего не хватает.
5. Инвариант двух рендеров: правило рендера должно быть реализуемо и в превью
   (gostRender.ts/paginate.ts), и в DOCX (gost.py) — отметь, если какая-то
   сторона проблемная.

Ничего не правь без моего запроса — только отчёт: список находок по убыванию
важности, в конце — вопросы, требующие моего решения.

Расхождение с кодом само по себе не дефект спеки: отделяй изменение целевого
поведения от неоднозначности. Источник истины — принятый контракт. Проверяй
примеры, настройки и исключения обеих сторон; не объявляй ГОСТ проверенным
по комментариям реализации. Источники — docs/reference/formatting-rules.md,
выбранное поведение — specs. Отчёт — в задаче, без каталога audit.
