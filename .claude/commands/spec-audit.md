description: Сверка диффа со спеками и тестами перед коммитом
---

Сверь текущие изменения со спеками. Процесс SDD описан в docs/README.md.

Дифф: `git diff develop` плюс незакоммиченные и неотслеживаемые файлы
(если текущая ветка — develop, то `git diff HEAD` + untracked).

1. Найди в диффе изменения ПОВЕДЕНИЯ продукта, не отражённые в docs/specs/ —
   список с файл:строка. Рефакторинг без смены поведения нарушением не считается.
2. Найди пункты спек, которым дифф противоречит.
3. Для каждого пункта спеки, затронутого диффом: есть ли покрывающий тест?
   Используй ссылки на правила и матрицу docs/specs/verification.md,
   а также проверки в docs/specs/core.md. Существующие тесты ради названий
   правил не переименовывай. Для правил рендера тесты
   нужны на ОБЕИХ сторонах (gostRender.test.ts ↔ test_gost_layout.py /
   test_converter.py).
3а. Если дифф меняет поток из docs/architecture/flows/ или структуру
   сервисов — проверь, что схема обновлена в том же изменении.
4. Если дифф трогает фикстуру kalman-report.md — проверь, что изменены ОБЕ
   копии (frontend/src/fixtures/ и services/backend/tests/convert/data/).
5. Если в диффе есть решение, достойное ADR (были альтернативы, откат прежнего
   поведения), а ADR нет — предложи создать.

Итог — таблица «пункт спеки → код → тесты → статус (ок / дыра / противоречие)»
и вердикт: готов ли коммит по правилу «спека+код+тесты вместе».
Ничего не правь без моего запроса.

Отчёт возвращай в задачу/PR, каталог audit не создавай. Предложенные требования
отличай от принятых; наличие тестового файла не означает полного покрытия.
