## P1 — до публичного запуска

### 1. AST-блоклист не изолирует Python-код ИИ

**Место:** `services/backend/app/ai/matplotlib_exec.py:73`, `:94`, `:112`; `services/backend/Dockerfile`.

**Подтверждено:** `_check_ast` разрешает `import io` и `io.open(..., 'w')`. Разрешённый код создал контрольный файл исключительно в `/tmp/cwm-audit`. Полный matplotlib subprocess в этой среде не запускался, но его wrapper не запрещает этот доступ: `python -I` не является файловой или сетевой песочницей.

В Dockerfile нет `USER`; код выполняется с правами процесса контейнера. Сгенерированный скрипт может обращаться к доступной файловой системе. Фильтр построен на неполном списке запрещённых имён; добавление одного `io` не закроет класс обходов через библиотеки. Комментарий обещает защиту памятью контейнера, но compose не задаёт memory limit, а `_limits` не ограничивает адресное пространство. `capture_output=True` также копит stdout/stderr до завершения процесса.

**Исправить:** исполнять скрипты в отдельном ограниченном worker/container: непривилегированный пользователь, read-only filesystem, отдельный временный каталог, без сети, без секретов и без доступа к backend/БД; hard limits памяти, CPU, процессов, времени и вывода. AST allowlist полезен как дополнительный фильтр. Пока изоляции нет — отключить исполнение Python в публичном контуре. Альтернатива: принимать от ИИ декларативные данные графика и строить изображение доверенным кодом; меньше гибкости, значительно меньше поверхность атаки.

### 2. SSRF через HTTP redirect в обоих загрузчиках

**Места:** `services/backend/app/convert/images.py:52`, `services/backend/app/ai/web_images.py:68`.

**Подтверждено:** с настоящей логикой redirects httpx и `MockTransport` запрос к `https://public.example/image` перешёл на `http://127.0.0.1/internal`. `_is_private_host` получил только `public.example`; внутренний ответ был принят обоими загрузчиками. Реальных запросов во внутреннюю сеть не было.

Проверка hostname выполняется один раз до `follow_redirects=True`. Экспорт DOCX доступен любому зарегистрированному пользователю, который задаёт ссылку в Markdown; для этой ветки не нужны ИИ или prompt injection. Отдельно из кода виден разрыв между DNS-проверкой и DNS-разрешением HTTP-клиентом: защита не фиксирует проверенный адрес соединения.

**Исправить:** общий загрузчик для AI и DOCX; запрет автоматических redirects либо проверка каждого перехода с небольшим лимитом hops. Соединяться именно с проверенным публичным IP с корректными Host/SNI. Закрыть внутренние сети также на уровне egress. Проверять redirects на loopback/private/link-local IPv4/IPv6 и изменение DNS.

### 3. Размеры входных данных и скачиваний ограничиваются слишком поздно

**Места:** `convert/images.py:53`, `ai/web_images.py:69`, `ai/router.py:55`, `convert/models.py`; `frontend/src/pages/EditorPage.tsx:201`.

**Подтверждено для HTTP:** при тестовом лимите 8 байт загрузчики прочитали все 16 байт ответа и только затем отклонили его. Реальный лимит 10 МБ аналогично не ограничивает потребление памяти при чтении. AI-загрузки тоже сначала делают `await f.read()`, затем сравнивают длину. JSON `assets` не имеет суммарного лимита на уровне модели. Compose публикует `8000`, поэтому лимит nginx нельзя считать обязательной защитой backend.

**Исправить:** читать потоком с прекращением по лимиту, проверять и Content-Length, и фактически прочитанный объём; лимитировать суммарный размер ассетов, число изображений и параллельных конвертаций. Для `.zip` использовать ограничения количества файлов и распакованных байтов и распаковку вне UI thread. ZIP-бомбы/нагрузочные атаки не запускались: ZIP-часть — вывод из `unzipSync` без ограничений.

### 4. Нет контроля стоимости публичного AI API

**Места:** `services/backend/app/ai/router.py:36`, `:78`, `:102`, `:170`; `app/auth/router.py:38`.

**Подтверждено чтением кода:** регистрация открыта; `/plan` и `/analyze-prompt` вызывают модели без per-user/per-IP квоты. `has_active` ограничивает только активную generate/edit-задачу одного user ID, но не число аккаунтов, частоту планирования и суммарный расход. Проверка generate делается до `await f.read()` и резервирования задачи, поэтому при асинхронном чтении нескольких запросов возможно пройти её конкурентно; эта гонка отдельно не воспроизводилась.

**Исправить:** атомарное резервирование слота задачи; rate limit регистрации/login/AI; квоты токенов или стоимости на пользователя и общий бюджет сервиса; ограниченная очередь workers; лимит ответа модели и сбор фактического usage. При достижении лимита возвращать явный отказ. Отдельная задача — корректная отмена: `asyncio.to_thread(resolve_figures, ...)` не прекращает уже работающий thread/subprocess автоматически.

### 5. При ошибке хранения интерфейс сообщает об успешном сохранении

**Места:** `frontend/src/lib/storage.ts:26`, `lib/assets.ts:22`, `hooks/useDocPersistence.ts:19`.

**Воспроизведено:** `localStorage.setItem` бросает `QuotaExceededError`; `manualSave` всё равно показывает «Документ сохранён», а после загрузки восстанавливается старый текст. Ошибки записи изображений также скрыты; новые картинки могут остаться только в памяти. Это особенно существенно, поскольку серверной копии документа нет.

**Исправить:** возвращать результат сохранения/ошибку, показывать реальный статус и давать резервный экспорт. Не удалять ассеты, если запись документа не удалась. Текст и картинки сохранять согласованно; для объёмных данных предпочтительна транзакция IndexedDB. Не обещать успешное сохранение до завершения операции.

### 6. Автоочистка картинок ломает Undo

**Места:** `frontend/src/hooks/useDocPersistence.ts:23`, `lib/assets.ts:97`.

**Воспроизведено:** добавить картинку → удалить её Markdown-ссылку → выполнить автосохранение → вернуть ссылку. `pruneAssets` уже удалил данные, `getAsset` возвращает `null`. Undo текста больше не восстанавливает документ целиком.

**Исправить:** учитывать историю документа или откладывать сборку неиспользуемых ассетов; удаление проводить явной операцией либо после безопасного retention. Проверка: удалить изображение, дождаться автосохранения, выполнить Undo, проверить превью и экспорт.

### 7. Запоздавший polling-ответ перезаписывает финальный AI-результат

**Место:** `frontend/src/hooks/useAiJob.ts:59`.

**Воспроизведено:** запрос A остаётся незавершённым; через 700 мс запрос B получает `done` и применяет `FINAL`; затем A возвращает старый `running/partial=OLD`. Хук записывает `OLD` поверх текста, снова выставляет `aiActive=true`, хотя polling-таймер уже остановлен. Получается старый документ и зависшая активная задача.

**Исправить:** последовательный polling через `setTimeout` после завершения запроса; AbortController и идентификатор поколения при смене job/unmount. После terminal state не принимать более старые ответы. Те же проверки должны защищать новую задачу от ответа предыдущей.

### 8. Аккаунты разделяют один локальный документ в браузере

**Места:** `frontend/src/lib/storage.ts:4`, `lib/assets.ts:7`, `auth/AuthContext.tsx:48`.

**Вывод из кода:** ключи документа/ассетов общие, выход удаляет токен и пользователя, но не отделяет их документы. После входа другим аккаунтом в том же browser profile редактор показывает ранее сохранённую работу. Это допустимая модель локального редактора только при явном объяснении, но у публичного приложения с аккаунтами создаёт риск раскрытия документа на общем компьютере.

**Исправить:** определить модель владения: отдельные namespaces пользователя и гостя, безопасная миграция при входе, явное управление локальными копиями. Не удалять работу молча при logout. Серверное хранение можно рассмотреть отдельно, но по правилам проекта такое архитектурное изменение требует ADR.

## P2 — корректность и восстановление пользовательских сценариев

### 9. DPI нарушает паритет изображения между превью и DOCX

**Места:** `frontend/src/lib/gostRender.ts:44`, `services/backend/app/convert/gost.py:700`.

**Подтверждено:** тестовый PNG 300×300 px с 300 DPI встроен в реальный DOCX шириной **25,4 мм**. Формула превью для тех же размеров даёт **79,375 мм**: `300/96*25.4`. Небольшие PNG сохраняются frontend без перекодирования, поэтому DPI может пережить импорт. Для больших картинок расхождение иногда маскирует ограничение максимальных габаритов, но это не устраняет причину.

**Исправить:** единая модель физического размера обычного изображения. Передавать рассчитанные размеры/метаданные или нормализовать вход. Сохранить отдельно корректный учёт масштаба PNG, полученного из Mermaid. Проверки с 72/96/150/300 DPI нужны на обеих сторонах.

### 10. Два парсера по-разному обрабатывают пустые столбцы и вложенное форматирование

**Место:** `services/backend/app/convert/md_parser.py:275`, `:43`, `:52`; `frontend/src/lib/markdown.ts`.

**Подтверждено:** строка таблицы `||B||` превращается в `['', 'B', '']` на frontend и `['B']` на backend. Python `strip('|')` удаляет все крайние разделители; значение сдвигается в первую колонку. На таблице с трёхколоночной следующей строкой это изменяет смысл данных при экспорте.

Другой пример: `**$x^2$**` даёт KaTeX внутри bold в превью, но backend возвращает `InlineRun(text='x^2', bold=True, math=None)`: формула превращается в текст до Pandoc.

**Исправить:** удалять ровно один внешний разделитель таблицы; переносить признаки форматирования на вложенные inline-элементы без потери типа math/code. Ввести общие fixtures и дифференциальные тесты парсеров, а не только независимые тесты каждой реализации.

### 11. AI-задача не восстанавливается после ошибок

**Место:** `frontend/src/hooks/useAiJob.ts:73`, `:98`, `:102`.

**Воспроизведено:** постоянный HTTP 404 приводит к десяти запросам за семь секунд; задача остаётся активной. Причина — все исключения считаются временными. После рестарта backend in-memory job исчезает, поэтому это реальный штатный сценарий. JWT 401 также не завершает опрос.

Отдельно подтверждено: streamed partial приходит через `setMd`, но при terminal `error` не передаётся в `onMdChange`, который запускает сохранение. Без отдельного пользовательского сохранения частичный результат может пропасть после reload. ID job хранится только в ref; переход на другой маршрут снимает polling, а server job продолжает работу и не подхватывается при возвращении.

**Исправить:** различать 401/403/404, 429 и временные сетевые ошибки; backoff и ограничение повторов; сохранять partial при ошибке и job ID для восстановления. Отсутствующую job завершать понятным состоянием с сохранением доступного текста.

### 12. Истёкшая сессия может выглядеть как неработающая кнопка DOCX

**Места:** `frontend/src/pages/EditorPage.tsx:309`, `:364`; `api/client.ts:43`; `auth/AuthContext.tsx:39`.

**Вывод из кода:** при 401 в download снова вызывается `requireAuth()`, но он проверяет наличие локального `user`, который при истечении JWT остаётся заполненным. Результат — нет перехода на login и нет сообщения об ошибке. В обратную сторону initial `/me` при любой сетевой ошибке удаляет токен, даже если это временная недоступность backend.

**Исправить:** единая обработка 401, сброс состояния сессии и повторный вход с сохранением документа. Не разлогинивать на сетевом сбое/5xx. Проверить, что ошибка скачивания всегда видима.

### 13. План может относиться к уже изменённой теме

**Место:** `frontend/src/pages/CreatePage.tsx:104`, `:133`, `:189`.

**Вывод из кода:** во время `planning` поля доступны (`disabled={starting}`). Изменение темы очищает план, но завершившийся запрос старой темы всё равно вызывает `setAnalysis` и `setPlan`. При генерации старая `analysis.topic` имеет приоритет над актуальным полем.

**Исправить:** хранить revision параметров и игнорировать устаревший результат либо блокировать изменение параметров на время построения. Проверка: задержать ответ планирования, поменять тему, вернуть старый ответ; старый план не должен становиться доступным для генерации.

### 14. Заявленного переносимого экспорта `.zip` нет

**Места:** `frontend/src/lib/docExport.ts`, `pages/EditorPage.tsx:337`; `CLAUDE.md`, `README.md`.

**Подтверждено поиском кода и обработчиков:** `.zip` импортируется, но экспорт реализован только для `.docx`; `docExport.ts` содержит имя файла и скачивание Blob. Создание архива с Markdown/картинками/настройками отсутствует. При localStorage-only это отсутствие полноценной переносимой резервной копии.

**Исправить:** архив с версией формата, Markdown, настройками титульника и всеми используемыми ассетами; тест export→import с полным восстановлением. Альтернатива — ограничить обещания документации, но для публичного сервиса резервный экспорт предпочтительнее.

## Дополнительные требования к публичному запуску

Эти пункты выявлены чтением кода/конфигурации; полноценный runtime security audit не выполнен.

- **JWT secret:** `app/config.py:8` допускает пустой secret при запуске вне compose. Compose проверяет наличие, но не достаточную длину. Проверять конфигурацию в startup и отказываться запускаться с пустым/слабым значением.
- **Отзыв сессий:** смена пароля меняет только hash. Старые JWT остаются пригодны до истечения срока, по умолчанию 168 часов (`security.py`, `auth/router.py:81`). Нужны token version/revocation и продуманная политика срока сессий.
- **Пароли:** API принимает до 100 символов, BCrypt использует первые 72 UTF-8 байта. Разные принятые пароли с общими первыми 72 байтами эквивалентны. Валидировать лимит в байтах либо мигрировать схему хеширования с сохранением совместимости; не обрезать молча.
- **Конкурентная регистрация:** проверка email и commit разделены; unique violation не преобразуется в 409. Обрабатывать IntegrityError и rollback. Нужен тест двух одновременных запросов.
- **Mermaid:** `securityLevel: 'loose'` для импортируемого/генерируемого текста требует отдельной браузерной проверки. Подтверждённого XSS в этом аудите нет. Без обоснованной потребности выбрать strict/sandbox, проверить диаграммы и добавить CSP как дополнительный уровень защиты.
- **Задачи:** in-memory store допустим в прототипе с одним процессом; для рестартов и нескольких workers нужна долговечная очередь/хранилище, recovery и контролируемый TTL. `/health` сейчас не проверяет БД и работоспособность конвертации; разделить liveness/readiness.
- **Документация:** обещание полного постраничного совпадения слишком сильное при найденном DPI-контрпримере. README/CLAUDE также говорят о нумерации источников «без точки», тогда как оба рендера и тесты используют точку по правилу вуза. Отделить профиль вуза от общих заявлений о ГОСТ. Не менять это поведение вслепую.
- **Сборка/деплой:** CI-конфигурации `.github` в дереве нет. В Docker frontend используется `npm install`, предпочтителен `npm ci`. Нет `.dockerignore`; build context избыточен. Ограничить сеть backend, явно определить TLS termination, backups/restore БД, сбор ошибок и метрик. Фактическую внешнюю инфраструктуру этот аудит не проверял.
- **Frontend performance:** сборка выдаёт основной chunk около 804 kB (gzip 246 kB) и Mermaid-related chunk около 1,45 MB. Это предупреждение сборщика, не доказательство медленного UI. Измерить initial load/editor typing в реальном браузере, затем лениво грузить editor/Mermaid. Число строк файла само по себе не причина рефакторинга.

## Почему зелёных тестов недостаточно

1. happy-dom не считает реальную геометрию страниц; прохождение 245 тестов не подтверждает пагинацию и scroll sync.
2. Все 32 converter-теста прошли без Pandoc. Проверки оформления формул ищут номера/отступы, но не гарантируют наличие `m:oMath`. Добавить обязательный тест нативной формулы в production image.
3. Тесты sandbox проверяют несколько запрещённых конструкций, но не доказывают изоляцию ОС. Нужны отрицательные тесты файлов/сети/процессов и ресурсных лимитов непосредственно worker-а.
4. Не покрыты quota errors, история ассетов, ответ polling не по порядку, потеря job после рестарта и устаревшее планирование.
5. Два парсера нуждаются в общем корпусе и сравнении семантики. Для layout — браузерные fixtures плюс DOCX→офисный renderer и сравнение страниц/TOC, отдельно по профилям шрифтов/офисных движков.

## Воспроизведение

Из корня проекта:

```bash
frontend/node_modules/.bin/vitest run --config audit/2026-09-10/vitest.config.mjs
```

Python-проверка требует `httpx`, `pydantic`, `python-docx`, Pillow и импортируемого backend:

```bash
PYTHONPATH=services/backend python3 audit/2026-09-10/backend_repro.py
```

`run_python.py` — вспомогательный bootstrap для доступного на этой машине кэша, **не** установка зависимостей проекта. `run_converter_tests.py` и `run_ai_tests.py` копируют существующие тесты во временный каталог и запускают доступные модули без общего conftest; поэтому их результат не подменяет полный integration suite.

`backend_repro.py` пишет только тестовый маркер `/tmp/cwm-audit/ast-marker.txt`, использует HTTP MockTransport и строит DOCX в памяти. Скрипты не читают `.env`, не вызывают платную LLM и не обращаются к внутренним HTTP-сервисам.
