# Архитектурные решения

ADR объясняет значимый выбор, его альтернативы и последствия. Актуальное
поведение хранится в specs, актуальное устройство — в architecture.
Не создавать ADR для каждого теста, исправления или CSS-правки.

- [ADR-0010: локальный MVP и монолит](0010-mvp-core.md).
- [ADR-0011: сгенерированные страницы и прокрутка](0011-scroll-generated-pages.md).
- [ADR-0012: MVP без аккаунтов и серверной БД](0012-no-accounts.md).
- [Шаблон](_TEMPLATE.md).

Номера прежних решений сохраняются, 0001…0009 не выдаются заново.
Следующее решение получает следующий свободный номер. Статусы: предложен,
принят, отклонён, заменён ADR-NNNN. При пересмотре создаётся новый ADR,
прежний помечается заменённым; исторические основания не переписываются задним числом.

Существующие решения изложены заново с сохранением ID и известных дат;
это не новая процедура принятия архитектуры. Изменение продуктового правила
само по себе не требует ADR, если архитектурного выбора нет.
