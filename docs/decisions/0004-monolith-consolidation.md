# ADR-0004: Схлопывание микросервисов в Python-монолит

Дата: 2026-07-19
Статус: действует

## Контекст

Бэкенд состоял из пяти сервисов: gateway, auth, document (Java/Spring) и
converter, ai (Python/FastAPI). Для соло-MVP с низкой стартовой нагрузкой это
переусложнение: пять юнитов деплоя, три JVM, сетевые хопы, распределённая
отладка, gateway ради маршрутизации внутрь — цена без выгоды (нет ни
независимого масштабирования, ни разных команд, ни разных требований к
релизам).

## Решение

Один Python + FastAPI монолит (`services/backend`) с модулями `auth`,
`documents`, `convert`, `ai`. JWT проверяется в самом сервисе
(`app/security.py:get_current_user_id`) — gateway и заголовок `X-User-Id`
удалены (SEC-1). Одна БД PostgreSQL (таблицы `users`, `documents`) вместо двух.

Язык — Python, потому что две незаменимые части уже на нём и переписывать их
рискованно: конвертер `gost.py` связан инвариантом постраничного паритета с
превью, а графики ИИ — matplotlib (только Python). Auth/documents (лёгкая
CRUD-часть) переписаны с Java на FastAPI + SQLAlchemy + PyJWT + bcrypt; хеши и
HS256-токены совместимы со старыми (тот же `JWT_SECRET`).

## Альтернативы

- **Java + Spring Boot монолит** — родной для автора, auth/documents уже есть,
  НО пришлось бы переписать конвертер на Apache POI (заново устанавливать
  паритет — главный риск проекта) и держать Python-сайдкар для matplotlib →
  уже не монолит.
- **Go** — самый лёгкий рантайм, но слабые DOCX-либы, нет matplotlib, нет
  опыта у автора; переписывание самого рискованного с нуля.
- **Оставить микросервисы** — отвергнуто: на текущей стадии это только
  операционные издержки.

## Последствия

- Деплой — один контейнер вместо пяти (проще и дешевле хостить; ближе к цели
  «качественный MVP к релизу»).
- SEC-1 упростился: проверка JWT — одна FastAPI-зависимость; внутренний
  `X-User-Id` и поверхность его подделки исчезли.
- Масштабирование — горизонтальное (N копий за балансировщиком); распил на
  сервисы вернётся только при реальной разнородной нагрузке.
- Java-код (auth/document/gateway) и отдельные converter/ai удалены; их логика
  и тесты перенесены в `services/backend`.
