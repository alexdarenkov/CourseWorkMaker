# Спека: Диалект Markdown

Какой Markdown понимает редактор и во что каждая конструкция превращается
в превью и в DOCX. Реализуется ДВАЖДЫ (главный инвариант проекта): парсеры
`frontend/src/lib/markdown.ts` ↔ `services/converter/app/md_parser.py` обязаны
давать одинаковую блочную модель, рендеры `gostRender.ts` ↔ `gost.py` —
идентичный результат вплоть до номеров страниц.

Детали вёрстки (интервалы, переносы, разрезы абзацев) — предмет будущих
`gost-layout.md` и `pagination.md`; здесь — только «конструкция → смысл».

Префикс ID: `MD`. Все пункты — `as-built` (выписаны из кода 2026-07-14).
Покрытие тестами по пунктам не инвентаризовано — сверять при первом изменении
области (`/spec-audit`); базовые тесты: `frontend/src/lib/gostRender.test.ts`,
`services/converter/tests/test_converter.py`, `tests/test_gost_layout.py`.

## MD-1. Раздел `#` — `as-built`

`# Название` → раздел «N Название» с новой страницы. Номер присваивается
автоматически; явный номер, набранный в тексте заголовка, срезается
(`stripHeadingNumber`), хвостовая точка заголовка срезается.

- Реализация: `markdown.ts` ↔ `md_parser.py` (парсинг), `gostRender.ts` ↔ `gost.py` (нумерация)

## MD-2. Структурные заголовки — `as-built`

Заголовок `#`, начинающийся со слов *введение, заключение, список, содержание,
реферат, определения, обозначения, сокращения, приложени…* (регэксп
`isStructural`, регистронезависимо) — структурный элемент ГОСТ: прописными,
по центру, БЕЗ номера.

- Реализация: `markdown.ts:isStructural` ↔ `md_parser.py`; рендер `gostRender.ts` ↔ `gost.py`

## MD-3. `# Реферат` первым заголовком — `as-built`

Страницы реферата идут ДО содержания и в содержание не входят.

- Реализация: `gost.py:_split_referat` (outlineLvl=9 исключает из поля TOC) ↔ `paginate.ts`

## MD-4. Подразделы `##` / `###` — `as-built`

`##` → подраздел «N.M Название», `###` → пункт «N.M.K Название»; нумерация
автоматическая, с новой страницы НЕ начинаются.

- Реализация: как MD-1

## MD-5. Подпись `Таблица: Название` — `as-built`

Строка `Таблица: Название` непосредственно перед GFM-таблицей → подпись
«Таблица N — Название» слева над таблицей. Таблица без строки-подписи
остаётся таблицей без номера/подписи.

- Реализация: `markdown.ts` (pendingTab) ↔ `md_parser.py`; рендер `gostRender.ts` ↔ `gost.py`

## MD-6. Подпись `Рисунок: Название` — `as-built`

Строка `Рисунок: Название` непосредственно перед `![…](…)` или ```` ```mermaid ````
→ подпись «Рисунок N — Название» по центру ПОД иллюстрацией.

- Реализация: `markdown.ts` (pendingFig) ↔ `md_parser.py`; рендер `gostRender.ts` ↔ `gost.py`

## MD-7. Формулы `$$…$$` и `$…$` — `as-built`

`$$…$$` (в т.ч. многострочные) → выключная формула Word (OMML) по центру
с номером «(N)» у правого поля. `$…$` → формула внутри строки текста.
Абзац сразу после формулы, начинающийся со слова «где», — пояснение:
каждое пояснение отдельным абзацем с красной строки (`splitGde`).

- Реализация: `markdown.ts` ↔ `md_parser.py`; превью — KaTeX (`katexHtml`), DOCX — pandoc→OMML (`omml.py`)

## MD-8. Листинги ```` ```lang ```` — `as-built`

Блок кода → листинг в рамке, Courier New 12 пт.

- Реализация: `gostRender.ts` ↔ `gost.py`

## MD-9. Mermaid-диаграммы — `as-built`

```` ```mermaid ```` → фронтенд рендерит диаграмму в PNG
(`mermaidRenderer.ts`, pHYs-плотность синхронизирует размеры с превью)
и передаёт конвертеру в `assets`; подпись — через MD-6.

- Реализация: `mermaidRenderer.ts`; конвертер встраивает как обычную картинку

## MD-10. Списки — `as-built`

`- пункт` → маркер «–», `1. пункт` → «N)». Пункт верстается как обычный абзац
с красной строки: маркер на абзацном отступе 1,25 см, после маркера NBSP
(текст не отрывается), продолжение длинного пункта — к ЛЕВОМУ полю,
висячего отступа НЕТ.

- Реализация: `gost.py:_list` (first_line_indent без left_indent) ↔ `gostRender.ts:renderAll` (text-indent:12.5mm)
- Решения: ADR-0001

## MD-11. Список источников — `as-built`

Нумерованный список в разделе «СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ» — та же
вёрстка, что MD-10, но номер «N.» — С ТОЧКОЙ, без скобки.

- Реализация: `gostRender.ts` ↔ `gost.py`
- Решения: ADR-0003 (вуз требует точку вопреки ГОСТ 6.16)

## MD-12. Разрыв страницы `---` / `***` — `as-built`

Горизонтальная линейка → принудительный разрыв страницы (и в превью, и в DOCX).

- Реализация: `markdown.ts` (type pagebreak) ↔ `md_parser.py`

## MD-13. Переносы строк — `as-built`

Любой перенос строки в редакторе = перенос строки в выводе. Пустая строка =
новый абзац. Абзац, содержащий переносы, выравнивается по ЛЕВОМУ краю
(а не по ширине).

- Реализация: `markdown.ts:joinPara` ↔ `md_parser.py`

## MD-14. Пустые строки — `as-built`

Пустые строки пользователя — НАСТОЯЩИЕ пустые абзацы DOCX (Word показывает их
и в начале страницы; превью их не гасит). Исключение: пустые строки сразу
после заголовка «съедаются» — между заголовком и текстом лишнего пустого
абзаца не бывает (`dropBlankAfterHeading` ↔ `_drop_blank_after_heading`).

- Реализация: `markdown.ts` ↔ `md_parser.py`; `gost.py:build` (needs_lead/pending_free) ↔ `paginate.ts`
- Решения: ADR-0002

## MD-15. Цитата `>` — `as-built`

Блок цитаты → курсив с отступом слева 12,5 мм, без вертикальных зазоров.

- Реализация: `gostRender.ts` (type quote) ↔ `gost.py`

## MD-16. Изображения — `as-built`

`![alt](asset:<key>)` — картинка из локального хранилища ассетов (передаётся
конвертеру в `assets`); `![alt](https://…)` — конвертер скачивает при экспорте
(SSRF-защита, лимит 10 МБ); отсутствующая/недоступная картинка → заглушка-рамка
125×62 мм на обеих сторонах. px→мм по 96 dpi, если плотность не задана в PNG.

- Реализация: `assets.ts`, `images.py`, `gostRender.ts` ↔ `gost.py`
