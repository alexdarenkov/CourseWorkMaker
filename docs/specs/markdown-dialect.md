# Markdown для конвертера

Статус: предложен. Здесь — поддерживаемый синтаксис и результат его чтения.
Оформление DOCX задаёт [formatting.md](formatting.md). Markdown не описан в ГОСТ:
связь между синтаксисом и документом выбирает приложение.

## Абзацы, переносы и пустые строки

```md
Первая строка
Вторая строка

Новый абзац
```
Результат: два абзаца; в первом сохранён перенос строки.
Одна пустая строка разделяет абзацы. Каждая дополнительная создаёт пустую строку
в документе. Сразу после заголовка дополнительные пустые строки убираются.
Пробелы по краям обычной строки удаляются; в листинге сохраняются.
Обратная косая черта в конце строки удаляется, перенос остаётся.

## Заголовки

```md
# Метод
## Расчёт
### Исходные данные
```
Три уровня: раздел, подраздел, пункт. Номера добавляет конвертер.
Ручной номер в начале и точка в конце удаляются: `## 4.3 Расчёт.` → «Расчёт».
Сейчас `####`–`######` сводятся к третьему уровню; это ограничение приложения,
не правило ГОСТ. `#Без пробела` — обычный текст.
Пропущенный уровень и единственный пункт требуют решения в [оформлении](../reference/formatting-rules.md#что-нужно-решить).

## Inline-оформление

- `**текст**` — полужирный.
- `*текст*` — курсив.
- Одинарные backticks — код внутри текста.
- `$x^2$` — формула внутри текста.
- `[название](URL)` — подчёркнутое название; активная ссылка пока не обязательна.

HTML не исполняется. Вложенная формула или код не должны превращаться в обычный текст
из-за внешнего выделения. Произвольная вложенность всех конструкций не обещается.
Замена `—` на `–` сейчас применяется к обычному тексту, но не к коду и LaTeX;
нужно отдельно решить, сохранять ли эту замену.

## Списки и цитаты

```md
- Первый элемент
- Второй элемент

7. Первый шаг
9. Второй шаг
```
Числа исходника не определяют результат: шаги станут `1)` и `2)`.
Пустые строки между нумерованными пунктами не сбрасывают счётчик;
обычный текст или другой блок сбрасывает. Вложенные списки пока не поддерживаются. Буквенные пункты `а)`, `б)` и далее распознаются как отдельные пункты; буквы сохраняются из исходника и не влияют на счётчик числового списка. Буквы ё, з, й, о, ч, ъ, ы, ь не используются.

Строки с `>` образуют цитату. Соседние строки цитаты соединяются пробелом.
Маркер источников отдельно описан в [оформлении](../reference/formatting-rules.md#перечисления-и-библиография).

## Таблицы и подписи

```md
Таблица: Результаты
| Метод | Ошибка |
| --- | --- |
| A | 0,1 |
```
Первая строка ячеек — шапка, строка `| --- | --- |` в документ не попадает.
Ячейки разделяются `|`; пустые крайние ячейки сохраняются. Выравнивание через
двоеточия в разделителе пока не поддерживается. Для однозначного ввода ставим
внешние `|` и одинаковое число ячеек в каждой строке.

`Таблица: …` относится к следующей таблице, `Рисунок: …` — к следующему изображению
или Mermaid. Регистр этих слов не важен. В примерах ставим подпись прямо перед объектом.
Нужно решить, как обрабатывать подпись без объекта, повторную подпись и посторонний
текст между ними: сейчас подпись может потеряться или привязаться слишком далеко.

## Код, Mermaid и формулы

````md
```python
  x = 1

  print(x)
```
````
Результат: листинг с исходными пробелами и пустой строкой. Язык не запускает код.
Если язык `mermaid`, содержимое становится схемой и получает подпись рисунка.

```md
$$F=ma$$

где F — сила; m — масса; a — ускорение.
```
`$$…$$` — отдельная формула. Допустимы отдельные строки с открывающим и закрывающим
`$$`. В пояснении части через `;` становятся отдельными строками.
Первое пояснение начинается с «где» и содержит тире.

## Изображения и разрыв страницы

```md
Рисунок: Схема установки
![Схема](asset:img-example)

---
```
Изображение стоит отдельной строкой. Ссылка `asset:…` указывает на загруженный ресурс;
допустимые внешние ссылки описаны в [API](api.md#размеры-и-изображения).
Отдельная строка `---` или `***` — разрыв страницы, не горизонтальная линия.
В примерах отделяем её пустыми строками; внутри листинга это обычный код.

## Неполный и неподдерживаемый ввод

Пока нужно выбрать поведение для незакрытого кода/формулы, `|` внутри ячейки,
таблиц с разным числом ячеек и строки `***` сразу после текста без пустой строки.
Не закрепляем случайный результат текущего парсера как правило.
Сноски и автоматические ссылки на объекты требуют
отдельного синтаксиса. До его выбора не считаем их поддерживаемыми.
