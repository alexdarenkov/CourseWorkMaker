# API конвертации и границы

Статус: предложен. Принятые ограничения — в [core.md](core.md).

## Запрос и ответ DOCX

`POST /api/convert/docx`, JSON, без авторизации.
Поля: markdown (обязателен), docName (default «Курсовая работа»), settings, assets.
Настройки документа передаются в camelCase. Пять переключателей по умолчанию
включены, текстовые поля титульника пустые. Настройки редактора не меняют DOCX.
assets: словарь src → data-URL/base64; `mermaid-N` связывает готовый растр со схемой.

Пример минимального тела: `{"markdown":"# Метод\n\nТекст","settings":{"titlePage":false,"toc":false}}`.
Успех: 200, бинарный DOCX, MIME
`application/vnd.openxmlformats-officedocument.wordprocessingml.document`,
Content-Disposition attachment с безопасным UTF-8 именем и расширением .docx.
Символы пути и переводы строк в имени не создают путь/дополнительный заголовок.

Ошибки: невалидная модель — 422;
слишком большой body — 413; заняты слоты — 429; сбой сборки — 500
с пользовательским сообщением без traceback. Слоты освобождаются и при сбое.
Приёмка: HTTP-тест без авторизации, валидный ZIP-контейнер DOCX, безопасное имя,
невалидный запрос, повторный запрос после сбоя.

## Размеры и изображения

- HTTP body — 32 МиБ до JSON-декодирования.
- markdown — 2 000 000 символов.
- docName — 255 символов.
- Каждое текстовое поле титульника — 10 000 символов.
- assets — 256 записей.
- Ключ asset — 2048 символов.
- Значение asset — 14 × 1024 × 1024 символов.
- Сумма значений assets — 24 × 1024 × 1024 символов base64/data-URL.
- Внешнее изображение — 10 МиБ скачанных данных.
- Разные внешние URL за конвертацию — 16.
- ZIP — 32 МиБ сжатых/распакованных, 512 записей.
- Обычный импортируемый файл — 8 МиБ.

Внешние изображения: только HTTP(S), порты 80/443, все DNS-адреса публичные.
Redirect, private/multicast IP и сетевые обходы проверки запрещены;
ограничение размера проверяется во время чтения. Повторный URL кэшируется
на время одной конвертации. Обычный PNG/JPEG не перекодируется при вставке,
остальные поддерживаемые браузером форматы нормализуются в PNG ([Форматы изображений](core.md#форматы-изображений)).

Приёмка: значение на границе/сверх границы, redirect на private host,
превышение потоком, повторный URL. Сетевые тесты используют моки, не произвольные
внешние серверы. Backend-модель ограничивает длину Markdown через 422;
413 относится прежде всего к body — различать эти уровни проверки.

## Исполнение и валидность

Не более двух параллельных конвертаций на процесс; третий запрос не ждёт,
а получает 429. В нескольких workers лимит применяется отдельно к каждому.
Недопустимые XML 1.0 символы в тексте документа/титульника отклоняются до сборки.
Корректные Unicode, табуляции и переводы строк не теряются. Mermaid работает
в strict; Markdown и листинги не исполняют Python/JavaScript на сервере.

Пример: NUL в markdown → 422, а кириллица и формулы → валидный DOCX.
Приёмка: production image с Pandoc, native OMML, конкурентные HTTP-запросы,
освобождение слота после ошибки. Отсутствие Pandoc не считается доказательством
соответствия формульного экспорта: skipped тест нужно указывать отдельно.

## Публичный reverse proxy

Nginx принимает body до 32 МиБ, ограничивает экспорт до 6 запросов/минуту на
IP (burst=3, без ожидания) и 2 одновременных запросов на IP. Переполнение
возвращает 429 JSON, превышение body — 413 JSON. Заголовок X-Forwarded-For
от клиента не позволяет обойти лимит; доверяется только отдельный TLS-прокси.
`/health` доступен через прокси. Неизвестные `/api/*` возвращают 404,
отсутствующие `/assets/*` — 404 вместо HTML приложения. HTML требует revalidation,
assets с хешем кэшируются на год. Ответы содержат CSP, запрет встраивания во
frame, nosniff и no-referrer. Тела документов и изображения не пишутся в access log.
Приёмка: `scripts/release_smoke.py`, отдельный короткий burst невалидных запросов
с разными поддельными X-Forwarded-For должен всё равно закончиться 429.
