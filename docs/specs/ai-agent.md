# Спека: ИИ-агент

Поведение ИИ-сервиса (`services/ai/`) и его UI (`AiConsole.tsx`, `EditorPage.tsx`).
LLM — через OpenAI-совместимый прокси Polza.ai; конкретные модели скрыты за
уровнями качества `AI_MODEL_FAST`/`AI_MODEL_BALANCED`/`AI_MODEL_QUALITY`
(формат `provider/model`). Схема потока — `docs/architecture/flows/ai-generation.md`.

Префикс ID: `AI`. Все пункты — `as-built` (выписаны из CLAUDE.md и кода 2026-07-15;
правка/нормоконтроль упрощены 2026-07-18, см. AI-6/AI-8).

## AI-1. Конвейер генерации — `as-built`

План (строгий JSON) → генерация разделов ПО ОДНОМУ с контекстом плана и
загруженных файлов → самопроверка «нормоконтролёром» (temperature=0) →
программный линт структуры + исправляющий вызов → построение графиков.

Чистая логика — функции уровня модуля в `agent.py`, тестируемые без LLM:
`normalize_outline` (нормализация плана), `ensure_single_heading` (страховка
заголовков), `lint_document` (программный линт структуры, AI-8), бюджет слов.

- Реализация: `services/ai/app/agent.py`
- Тесты: `services/ai/tests/test_agent.py`

## AI-3. Графики matplotlib — `as-built`

**Зачем**: Polza — чистый прокси моделей (без code-interpreter), поэтому
скрипты исполняются только на нашей стороне.

При `include_images` ИИ пишет скрипты в блоках ` ```matplotlib `;
`figures.py`/`matplotlib_exec.py` выполняют их в изолированном подпроцессе
(ограничения — SEC-5) и встраивают PNG как ассеты `asset:fig-N`. Ассеты
возвращаются в ответе job вместе с markdown: фронт кладёт их в хранилище,
конвертер встраивает в DOCX.

- Реализация: `figures.py`, `matplotlib_exec.py`
- Тесты: `tests/test_figures.py`, `tests/test_sandbox.py`

## AI-5. Стриминг генерации — `as-built`

`_write_section` пишет через `llm.astream` и передаёт НАКОПЛЕННЫЙ текст в
`on_chunk` (троттлинг 0,4 с) → `job.partial` = готовые разделы + растущий
черновик текущего. Фолбэк на `ainvoke`, если прокси/модель не стримит.

Фронт поллит job каждые 700 мс и пишет partial ПРЯМО в редактор с
автоскроллом («текст печатается» в превью; `trackAiJob` в хуке `useAiJob`).

```gherkin
Сценарий: отмена во время генерации
  Дано генерация уже написала часть разделов (partial)
  Когда пользователь нажимает «Отменить»
  Тогда уже написанные разделы ОСТАЮТСЯ в редакторе
```

- Реализация: `agent.py:_write_section`, `hooks/useAiJob.ts:trackAiJob`
- Тесты: `tests/test_streaming.py`, `hooks/useAiJob.test.tsx`
- Решения: стриминг введён 2026-07-13; diff-просмотр и история откатов убраны
  2026-07-18 — отмена всегда оставляет partial в редакторе

## AI-6. Правка документа — `as-built`

`POST /edit` — правка ВСЕГО документа по свободной инструкции: модель получает
документ целиком и возвращает полный итоговый markdown. Результат применяется
в редактор СРАЗУ (как правка в Claude Code) — без diff-просмотра и без истории
откатов; дальше пользователь правит текст руками в редакторе. Режим выбирается
сегментом «Правка» в консоли (AI-10).

- Реализация: `agent.py:edit`, `hooks/useAiJob.ts`, `AiConsole.tsx`
- Тесты: `hooks/useAiJob.test.tsx`, `components/AiConsole.test.tsx`
- Решения: точечная правка раздела (`/edit-section`), diff-просмотр и история
  откатов (стрелки в шапке) убраны 2026-07-18 — правка сгенерированного текста
  делается вручную

## AI-8. Программный линт структуры — `as-built`

Проверка оформления БЕЗ LLM (обязательные разделы, подписи таблиц/рисунков,
ссылки на источники `[N]`, заголовки, патологические габариты PAG-11) живёт
ТОЛЬКО как внутренний шаг конвейера генерации (`lint_document`, AI-1): она
чинит текст, который пишет модель. Отдельного пользовательского нормоконтроля
(кнопка-щит, `POST /lint`, проверка доступности URL источников) больше нет —
убран 2026-07-18 вместе с `lint_user_document`/`sources.py`.

- Реализация: `agent.py:lint_document` (+ `_lint_captions`/`_lint_citations`/
  `_lint_oversized`)
- Тесты: `tests/test_agent.py`

## AI-9. Валидация промпта — двухступенчатая, fail-open — `as-built`

**Зачем**: отсечь мусорные промпты ДО платного вызова больших моделей,
но никогда не блокировать пользователя из-за сбоя валидатора.

Ступень 1 — локальные регэкспы (`validatePrompt` в AiConsole): ≥5 символов,
≤4000, «есть ≥3 буквы подряд», правка при пустом документе — ошибка.
Ступень 2 (ТОЛЬКО генерация) — быстрая модель (t=0, строгий JSON):
`POST /analyze-prompt` (`prompt_check.py`) валидирует промпт И извлекает тему
(≤500)/требования/target_pages/явные `include_*` (null = не упомянуто — тоггл
не трогается); тогглы в ⚙ подстраиваются с тостом. У правки ступени 2 нет —
после локальной проверки инструкция уходит прямо на `/edit` (`/validate-prompt`
убран 2026-07-18).

Вызов fail-open: сбой или отсутствие ключа НЕ блокируют отправку.

```gherkin
Сценарий: валидатор недоступен
  Дано быстрая модель возвращает ошибку 500
  Когда пользователь отправляет осмысленный промпт
  Тогда генерация запускается (fail-open)
```

- Реализация: `AiConsole.tsx:validatePrompt`, `services/ai/app/prompt_check.py`
- Тесты: `tests/test_prompt_check.py` (`parse_analysis`), `components/AiConsole.test.tsx`

## AI-10. Консоль AiConsole — `as-built`

Точка входа ИИ (заменила модалку AiModal, 2026-07-13): консоль ПОД
редактором, всегда видна, сворачивается явной кнопкой «Скрыть» (состояние
в localStorage). БЕЗ чата: вывод агента идёт ТОЛЬКО в редактор (md), ошибки —
тостами, статус — строкой прогресса с отменой. Режим выбирается ЯВНО
сегмент-переключателем «Новый отчёт | Правка» (авто-синк с пустотой
документа; «Новый» при непустом — с confirm о замене). 📎 файлы и ⚙-поповер
настроек отчёта — в нижнем ряду, круглая стрелка-отправка справа.

Стартовый `SAMPLE_MD` — инструкция использования с примерами промптов;
документ, РАВНЫЙ ему, считается пустым (режим «Новый отчёт», генерация
заменяет без confirm).

- Реализация: `AiConsole.tsx`, `lib/sample.ts`
