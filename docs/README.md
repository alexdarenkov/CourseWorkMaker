## Где что лежит

- `frontend/src/lib/` — чтение Markdown и построение превью.
- `services/backend/app/convert/` — чтение Markdown и создание DOCX.
- `frontend/tests/`, `services/backend/tests/` — тесты.
- `docs/specs/` — требования к приложению.
- `docs/reference/` — свод источников и правил оформления с отметками о согласовании.
- `docs/architecture/` — как устроен код.
- `docs/decisions/` — причины важных архитектурных решений.
- [AGENTS.md](../AGENTS.md) — инструкции агентам и команды запуска.

## Как менять правила и код

1. Исправляем нужное правило в спеках. Пишем условие, результат и пример.
2. Если есть несколько вариантов, сначала выбираем один. Пока правило не выбрано,
   оно имеет статус «предложен». «Принят» означает, что правило обязательно.
3. По принятому правилу меняем код и тесты. Для общего оформления проверяем DOCX и превью.
4. Если изменились модули или передача данных — обновляем архитектуру.
   Для важного выбора с альтернативами добавляем ADR.

Для правки только документации код менять не нужно. Старые версии остаются в Git.
Новую спеку создаём для отдельной темы, а не для каждой задачи.

ГОСТ, методичка и выбранные правила приложения могут различаться. Такие различия
записываем прямо.
