# Публикация на VPS

Для первого запуска: Linux VPS в РФ, 2 vCPU, 4 ГБ RAM, 40–50 ГБ SSD,
публичный IPv4 и домен. Backend ограничен 1 ГБ; оставшаяся память нужна
системе, прокси и сборке frontend. Это начальная конфигурация, не гарантия
пропускной способности: конвертер допускает две работы одновременно.

## Первый запуск

1. Установить Docker Engine и Compose plugin из официального репозитория Docker.
2. Создать A-запись домена на IPv4 VPS. AAAA добавлять только при работающем IPv6.
3. Разрешить входящие TCP 80/443 и UDP 443. SSH разрешить только с доверенных
   адресов. Не открывать 3000/8000. Проверять доступ извне: Docker-публикация
   портов может обходить некоторые правила host firewall.
4. Скопировать проверенную версию репозитория. В корне выполнить:

```bash
export DOMAIN=texturn.example.ru # заменить своим доменом
# Используется самостоятельная production-конфигурация, без dev compose.
docker compose -f docker-compose.production.yml config --quiet
docker compose -f docker-compose.production.yml up -d --build --wait
python3 scripts/release_smoke.py "https://$DOMAIN"
```

Caddy получает и обновляет TLS-сертификат автоматически, перенаправляет HTTP
на HTTPS. Для выдачи сертификата нужны правильный DNS и доступные 80/443.
Домен нужно задавать при каждом вызове Compose либо сохранить в локальном
`.env` на сервере (не коммитить). Не использовать HTTP-адрес вместо домена.

Внешние порты есть только у Caddy. Nginx доверяет X-Forwarded-For только от
172.30.47.2 — фиксированного адреса Caddy. При изменении подсети `edge` нужно
согласованно изменить `deploy/trusted-proxy.conf`. Чужим контейнерам эту сеть
не предоставлять. CDN перед Caddy требует отдельной настройки доверенных
прокси; произвольным X-Forwarded-For доверять нельзя.

Nginx ограничивает экспорт до 6 запросов в минуту на IP, допускает короткий
всплеск из 4 запросов и до 2 одновременных запросов на IP. Общий лимит backend —
2 конвертации на процесс. Пользователи за одним NAT делят лимит IP.
Превышение возвращает 429 с понятным JSON-сообщением. Это ограничивает обычную
перегрузку, но не заменяет защиту провайдера от распределённой атаки.

## Обновление и откат

Перед обновлением сохранить SHA предыдущей проверенной версии и теги/ID
образов; не перетирать единственную копию образа до проверки релиза.
Разворачивать новый checkout отдельного release tag, после сборки выполнять
`up -d --wait` и smoke-проверку. Для отката запускать Compose из предыдущего
checkout с прежними образами. Внешний домен и имя проекта `texturn` сохранять.
`restart` не применяет изменения образов или переменных окружения.

Nginx повторно разрешает имя backend через Docker DNS после замены контейнера.
HTML отдаётся с revalidation, хешированные assets кэшируются на год.
После выпуска уже открытая вкладка может потребовать обновления: сохранять
старые статические assets при бесшовных обновлениях — отдельное улучшение.

## Эксплуатация

```bash
docker compose -f docker-compose.production.yml ps
docker compose -f docker-compose.production.yml logs --tail=100 backend frontend caddy
docker stats --no-stream
```

Проверять HTTPS `/health` внешним мониторингом. Он проверяет доступность цепочки
прокси → backend, но не Pandoc; периодический smoke-экспорт проверяет и формулы.
Healthcheck только отмечает unhealthy: Docker сам не перезапускает зависший
процесс по этому статусу. `restart: unless-stopped` помогает при завершении
процесса и перезагрузке VPS. Следить за OOM, диском, временем конвертации и 429/5xx.
Логи ротируются: 3 файла по 10 МБ на контейнер. Не включать логирование тел
запросов: там текст работ и изображения.

Сохранять конфигурацию и тома Caddy с сертификатами. Сервер не хранит работы:
backup VPS **не восстанавливает localStorage пользователей**. Данные браузера
привязаны к origin: смена домена, HTTP → HTTPS или порта не переносит черновик.
Перед сменой origin нужен импорт сохранённого ZIP; экспорт ZIP пока скрыт в UI.

## Перед выпуском

- Frontend tests/build, backend tests внутри production image с Pandoc.
- `npm audit` и `pip-audit`, smoke-тест HTTP и конфигурации nginx.
- Реальный Chrome: главная/редактор, светлая/тёмная темы, 375 и 1440 px,
  обе формы настроек, ввод/Undo, автосохранение после reload, импорт ZIP
  с текстом/рисунком/логотипом, экспорт Mermaid и формул.
- Dev-харнессы toc/code/wide/mixed/report и highlight; сравнение числа страниц
  и содержания с DOCX в Word/LibreOffice. Happy-dom этого не проверяет.
- DNS, настоящий TLS и доступность только нужных портов проверять на VPS.

Результаты конкретного прогона фиксируются в PR/CI, не в этом руководстве.
