# Путь документа

1. Пользователь вводит Markdown или импортирует файл.
2. `EditorPage` хранит текст и настройки. Изображения хранятся отдельно,
   в тексте остаются ссылки `asset:…`.
3. `useDocPersistence` сохраняет данные в localStorage. Несохранённый черновик
   остаётся в памяти при переходах внутри приложения.
4. Превью читает Markdown, оформляет блоки и раскладывает их по страницам.
5. При экспорте frontend отправляет текст, настройки и изображения в `/api/convert/docx`.
6. Backend проверяет запрос, собирает DOCX и возвращает файл.

Mermaid превращается в изображение перед передачей на backend.
Импорт ZIP меняет ссылки на изображения по блокам Markdown, не внутри кода.

Прокрутка связывает исходные строки с местами в превью. Титульник и содержание
не имеют своих строк, поэтому обрабатываются отдельно: [правило прокрутки](../../specs/core.md#синхронная-прокрутка).
