# Как устроен конвертер

Правила результата — в [своде правил оформления](../reference/formatting-rules.md).
Здесь только устройство кода.

## Превью

`markdown.ts` читает Markdown → `gostRender.ts` добавляет оформление и номера
→ `paginate.ts` измеряет HTML и собирает страницы.

KaTeX рисует формулы, Mermaid — схемы. `splitHtml.ts` делит длинный текст,
не разрезая формулу или изображение внутри. После готовности шрифтов и рисунков
`usePagination` запускает новый расчёт.

## DOCX

`convert/models.py` проверяет запрос → `md_parser.py` читает Markdown
→ `gost.py` создаёт документ через python-docx.

`images.py` загружает допустимые изображения. `omml.py` переводит LaTeX
через Pandoc в редактируемые формулы Word. Ошибка преобразования может дать
текст вместо формулы, поэтому отдельно проверяем наличие математического элемента.
Word/LibreOffice сам разбивает DOCX на страницы; backend не рисует страницы пикселями.

## Что общее

- Два парсера должны одинаково читать вход.
- Два рендера должны одинаково считать заголовки, таблицы, рисунки и формулы.
- Исходные координаты нужны только превью для каретки и прокрутки.
- Геометрия превью — в `pageGeometry.ts`; метрики строк — в `gostRender.ts`.
  Высота 24,15 pt для текста и 20,4 pt для кода — текущая калибровка, не числа ГОСТ.
- Ширины таблицы: вес столбца — длина самого длинного содержимого, ограниченная
  от 3 до 30; ширина пропорциональна весу. Для Unicode подсчёт длины двух языков
  нужно согласовать. Это алгоритм приложения.
- В DOCX стиль `Code Block` задаёт шрифт всему листингу, включая пустые строки.
  `Unlisted Heading` не даёт содержанию выбрать собственный заголовок.

## Где править

Синтаксис — оба парсера. Шрифт, подпись, номер — оба рендера. Переносы —
пагинатор превью и свойства абзацев/таблиц DOCX. После изменения геометрии
проверяем также прокрутку и каретку.

Известные места для будущей проверки: номер таблицы при autoNumber=false,
подпись без объекта, пропущенные уровни заголовков, свободные строки у формул
и в конце документа, таблица на несколько страниц. Сначала выбираем правило,
затем исправляем код.
