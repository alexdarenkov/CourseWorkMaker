# CourseWorkMaker · Texturn

Markdown-редактор курсовых работ с постраничным превью, оформлением по профилю
ГОСТ 7.32-2017 и экспортом DOCX. MVP работает **без ИИ-генерации**.

## Возможности

- Markdown с подсветкой, синхронной прокруткой и маркером каретки в превью.
- Титульный лист, содержание, нумерация разделов, таблиц, рисунков и формул.
- Локальные изображения, Mermaid-схемы и LaTeX-формулы.
- Автосохранение без постоянного индикатора; при ошибке — сообщение и повторная попытка.
- Импорт `.md`, собственных ZIP-копий и обычных архивов Markdown с изображениями.
- DOCX с нативными формулами Word (Pandoc) и полем содержания TOC.

**Документ хранится в браузере; аккаунтов нет.** На общем компьютере работа
доступна другим пользователям того же browser profile. Очистка данных браузера удаляет локальную работу.

Превью — отдельный браузерный renderer. Финальную раскладку нужно проверить в
Word/LibreOffice; при открытии DOCX обновить поля содержания. Полное постраничное
совпадение для произвольных документов и офисных движков не гарантируется.
Нумерация источников использует точку по принятому профилю вуза.

## Архитектура

```text
React / Vite → nginx → FastAPI → python-docx + Pandoc → DOCX
```

Backend — один Python-монолит. Java-сервисов, аккаунтов и БД, ИИ-агента, платных API, исполнения
генерируемого Python и платежей в MVP нет. Документы на сервере не сохраняются.

## Запуск

Нужны Docker и Docker Compose.

```bash
docker compose up --build
```

Откройте [приложение](http://localhost:3000). Регистрация не нужна.

Для разработки frontend:

```bash
docker compose up backend
cd frontend
npm ci
npm run dev
```

[Vite](http://localhost:5173) проксирует `/api` в backend на `localhost:8000`.
Этот порт в compose доступен только на loopback; наружу приложение отдаёт nginx.
Для публичного окружения подготовлен отдельный `docker-compose.production.yml`:
Caddy с автоматическим HTTPS, nginx с rate limiting, backend без внешнего порта.
Команды запуска, проверки и отката — в [руководстве по публикации](docs/architecture/deployment.md).

## Документ и ZIP

1. Откройте редактор, напишите текст либо загрузите `.md/.zip` кнопкой в тулбаре.
2. Добавьте локальные картинки и настройте титульный лист.
3. Изменения сохраняются автоматически. При ошибке не закрывайте вкладку и нажмите «Повторить».
4. «Скачать DOCX» создаёт готовый документ через backend.

Постоянная строка статуса и скачивание ZIP убраны из интерфейса. Импорт ранее
созданных ZIP остаётся доступным. Модуль ZIP сохранён в коде с тестами.

Локальные ассеты не удаляются автоматически при удалении Markdown-ссылки:
это позволяет Undo восстановить изображение. При достижении квоты браузера
вставка новой картинки отклоняется с сообщением; IndexedDB и сборка неиспользуемых
ассетов с учётом истории — возможный следующий этап.

ZIP-копии прежних версий содержат локальные изображения; внешние URL требуют сети.
ZIP ограничен 32 МиБ сжатых и распакованных данных и 512 записями. Отдельное
изображение — до 10 МиБ, Markdown-файл — до 8 МиБ и 2 млн символов.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/convert/docx` | `{markdown, docName, settings, assets}` → DOCX |
| GET | `/health` | Liveness процесса |

Авторизации нет. Все `/api/auth/*` и `/api/ai/*` удалены и возвращают 404.

Backend ограничивает body до 32 МиБ, ассеты до 256 записей / 24 МиБ base64 и
одновременные конвертации до двух на процесс (остальные получают 429).
Внешние изображения загружаются только с проверенных публичных IP на портах
80/443, без redirects и environment proxies, до 10 МиБ. Redirect-ссылку нужно
заменить прямым URL изображения. До 16 различных внешних URL на документ.

## Проверки

```bash
npm --prefix frontend run test
npm --prefix frontend run build

docker build -t cwm-backend services/backend
docker run --rm cwm-backend pandoc --version
docker run --rm -v "$PWD/services/backend/tests:/srv/tests:ro" cwm-backend python -m pytest tests -q -p no:cacheprovider
```

Backend-тесты используют HTTP-моки и не требуют БД. Проверка реальной формулы требует
Pandoc и выполняется в Docker/CI. В локальном окружении без Pandoc она пропускается.
Frontend-тесты используют happy-dom и не проверяют реальную геометрию страниц.
Для неё нужны dev-страницы `preview-test.html?doc=toc|code|wide|mixed|report`
и `highlight-test.html`, а также сверка результата DOCX в Word/LibreOffice.

CI запускает frontend tests/build, аудит зависимостей, backend tests в Docker
и smoke-проверку production-конфигурации через Caddy/nginx. Перед публичным
выпуском дополнительно нужны браузерные проверки, проверка восстановления
данных, Word/LibreOffice и настоящий TLS на выбранном домене.

## Ветки

- `develop` — основная ветка интеграции, база и цель PR для дальнейших фич.
- `mvp-core` — подготовка MVP без ИИ, затем PR в `develop`.
- `archive/ai-prototype` — сохранённые наработки с ИИ (`ec2fc07`).
- `main` — проверенные релизы из `develop`.

Рабочие ветки называются без префикса `codex/`. Архитектура, команды и инварианты
для разработчиков — в [AGENTS.md](AGENTS.md).
